Why this exists

Most home dashboards are assembled. This one is designed.

Home Assistant is an excellent home automation engine. Its dashboard is a grid you fill with cards, each written by a different person, each with its own spacing, motion, and idea of what a button feels like. It works — and it never quite feels like one product.

Hauser takes the other path. Everything on screen comes from a single set of design tokens, a documented interaction contract, and a performance budget that is treated as a requirement rather than an aspiration.

Room UI

Controls stay compact. The room stays visible.

The default panel keeps one narrow control surface beside the room illustration. More space is available when needed, but it is not the first impression and it is not the everyday default.

The interface follows the sun through Home Assistant, so nobody in the household ever reaches for a theme setting. Both pictures below are real screenshots of the same panel in the same state — switch between them.

The same panel, the same second — only the sun moved.

Room images

Photograph the room. That is the whole input.

Every room in Hauser carries an illustration of itself in three lighting states, and the picture follows the lights. The illustrations that ship with the product are of this house, which is no use to yours — so the room-image wizard makes yours from a photograph you take with your phone.

The picture on the left is a real input, not a demonstration shot. Evening light, a wide-angle phone lens, toys on the floor, the sofa half in shadow. Nothing was tidied and nothing was staged. The illustration on the right is what the pipeline made of it — and it is the living-room image that ships in the product today.

Input Even this photo is enough.

Output The same room, in the daylight state.

1 Your photo, your framing

Upload the picture, choose the crop and set the focus point that the room screen will hold on to. A few closed options — calm the clutter a little or a lot, keep this thing in particular — instead of a prompt box.

2 One correction, then the style

The first pass may correct perspective and composition moderately. After that, camera, geometry and object positions are frozen, and only the style is applied — so what comes back is still your room, not a stock living room that resembles it.

3 A whole set, or nothing

Day, evening and lights-off are generated as one set, reviewed together and published atomically to the image library. Assign it to a room from there, or keep the bundled illustration.

This is the one place where Hauser talks to a paid third party: the wizard needs your own OpenAI access, and your photo is sent there to be redrawn. That trade is stated before anything is uploaded, every paid step is confirmed by hand, and a running count of provider calls stays on screen. The wizard is not part of the public demo.

Interaction

It answers before the house does.

Tap a light and it turns on — on screen, immediately. The command travels to Home Assistant afterwards. When the house confirms, nothing visible happens, because the interface was already right.

When the house disagrees, the control animates back to the true state instead of quietly lying to you. Every intent is tracked, reconciled against the incoming state, and abandoned after a timeout. That reconciliation logic took longer than anything else in this project, and it is the reason the interface feels the way it does.

Everyday

The screens a household opens most.

Lights and rooms are what a home dashboard gets sold on. What a household actually touches every day is smaller than that: who still has to do what, and what is missing from the fridge. Those two got the same care as the room screens — and they are the reason people who never open Home Assistant open this.

Shopping list grouped by shop, reminders as post-its per person.

The same lists on the resting screen — touch one and you are in it.

A colour per person

Reminders are post-its grouped by family member, each in their own colour. Adding one is a tap beside that person's name — no form, no separate assignment step, nothing to explain to anyone.

Ticked off in the shop

On the phone the list stays grouped by shop, so it reads in the order you walk. Checking an item off takes a double tap — deliberate enough that a pocket cannot do it, and done items stay visible for a while, so a wrong one is never a loss.

Already on the resting screen

The ambient screen carries the week's appointments, the post-its and the shopping list without anyone unlocking anything. Touch the list and you land in the list; touch the week and you land in the calendar.

Energy

Honest about what it cannot measure.

Live load and daily consumption come from real power sensors, broken down per device and plotted across the day. The house behind this screenshot has no solar array and no grid meter, so those figures stay empty rather than being estimated into existence. An interface that invents numbers is worse than one that admits a gap.

Media

The film library is just another room.

Jellyfin is integrated rather than embedded: the shelves, the detail view and HLS playback with resume are built in the same design system as the light switches. Room audio runs through Home Assistant media players with the same controls — choosing what plays in the kitchen is no different from turning on the kitchen light.

Two shells

Same language, different hand.

The phone layout is not a squeezed panel. Navigation moves to the thumb, rooms become a drill-down instead of an overlay, and the destinations you use most sit in the bottom bar in an order you choose. The tokens, motion and interaction rules stay identical.

Beta status

A technical beta, in the open.

Hauser installs and runs today. Compatibility with the enormous range of Home Assistant setups is still growing, there is no support SLA, and it is built for trusted deployments on your own network rather than for the public internet.

What you get

  • A complete, working interface you can run and read
  • A documented design system, interaction contract and performance budget
  • A guided Home Assistant setup with versioned external configuration
  • AGPL licensed — fork it, run it, modify it; share your changes if you offer it to others

Worth knowing

  • No SLA and no promised response time
  • Device and Home Assistant coverage is still growing release by release
  • Intended for trusted local networks, not for internet exposure
  • Versions move fast; read the release notes before upgrading

The first installation outside this household is confirmed: Hauser was set up on an Asustor NAS running Linux on x86_64 with Docker Compose against Home Assistant Container — roughly eight areas and 370 entities, discovered automatically, with the first light under control ten minutes in. That report also found the current edge: media players, vacuums and some room-assigned switches were not picked up by discovery yet. Both halves of that are what a beta is for.

The full picture — supported entity domains, known limitations and what changed in each release — lives in the release notes and the README.

Install

One click on Home Assistant OS. Compose everywhere else.

Both paths end in the same guided setup: it scans Home Assistant, proposes rooms and devices, lets you correct the result and activates a validated configuration atomically. No source edits, no YAML.

Home Assistant OS & Supervised

As a Home Assistant App

  1. Add github.com/ralleur/hauser as an App repository.
  2. Select Hauser, install it, start it.
  3. Open the web UI and run the setup wizard.
Add the repository

A thin wrapper around the same image, with all state in Home Assistant's persistent storage — so App backups cover your household configuration. The packaging is marked experimental and has been verified on the maintainer's Home Assistant OS system so far.

Container, Docker hosts, NAS

With Docker Compose

  1. Copy .env.example to .env.
  2. Run docker compose up -d.
  3. Open port 4173 and run the setup wizard.
Read the install guide

Home Assistant Container has no App system, so this is the path there — and the one the first external installation confirmed. Backup, restore, update and rollback are documented end to end.
